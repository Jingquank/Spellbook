## Design Specificity Verdict

**LLM assessment.** The spine is authored for Spellbook and could not ship elsewhere unchanged: a contents page with leaders and page numbers that folds to follow the page being read, running heads, Settings as the spread past the last skill, a Notes margin whose output is a Brief to a named agent, generated Install artwork, and a vocabulary (guessed · name it · not a group · drift) that encodes the product's real epistemics. The book earns its place in the TOC, the margin and the page turn. It is decoration in the gutter gradients, in Settings-nav leaders that lead to blank values, and in "page 37 of 37" for Settings. The chrome is generic: the title bar is any dev tool, the Settings page is stock grouped rows, and the Mono register is a TUI file tree in a browser, brushing against the anti-reference "file managers that lead with paths". The biggest conceptual crack: a Register is defined as a voice, yet Folio has sort, filter, a cursor and a different order while Grimoire has none, so Mono is a power mode wearing a typeface.

## Overall Impression

The idea is right and the discipline is real: one book, one Reader, one loop back to the agent, and colour only where a state needs it. What lets it down is the last mile of every promise. Two "ask the agent" buttons only toast; the Mono register changes behaviour rather than voice; accessibility is claimed in DESIGN.md and contradicted by 18 contrast failures and an unreachable Increase Contrast palette. The single biggest opportunity: make every action that names the agent actually send a Brief, so the loop the product is built around is the only loop it has.

## What's Working

1. **The contents page as a real map.** Leaders and page numbers give extent and position for 36 skills at a glance, the open section follows the page being read, and "page 12 of 37" therefore means something. The book idea doing work, not costume.
2. **The Notes margin → Brief loop is honest.** Quote plus line range, one batch per file, the exact text previewable, a clipboard fallback when the server is gone, and a status line whose verbs change as the world changes. The tab never writes and the copy never pretends otherwise.
3. **Colour discipline.** Warm graphite everywhere; saturation only in tiles, agent marks and the word "drift", so the one state that needs attention is the only thing with colour. Schibsted Grotesk and Commit Mono hold across both registers.

## Priority Issues

1. **[P1] Accessibility is promised and not delivered.** Tertiary text on the grouped surface measures 4.1:1 in 18 places in Settings; the disabled primary is 2.3:1; footer and legend text is 11 px in 22 px targets; and the Increase Contrast palettes in `tokens.css` key on `:root:not([data-theme])`, which never matches because next-themes stamps `data-theme` even for System. The Mono tree has no roles, no focus and reads box-drawing glyphs aloud. **Why it matters:** DESIGN.md claims WCAG AA and full keyboard operation; a screen-reader or low-vision user cannot use half the product. **Fix:** use `--sb-text-secondary` for row sub-labels on grouped surfaces (or darken tertiary there), raise chrome text to 12 px, resolve `prefers-contrast` in JS and stamp `hc-light`/`hc-dark`, give the tree `role="tree"`/`treeitem` with roving `tabIndex` and `aria-hidden` glyphs, add `aria-live` to the status line. **Command:** /impeccable audit, then /impeccable polish.
2. **[P1] Two "ask the agent" actions are toasts.** The Drift popover's "How to reconcile" and More → "Ask Claude Code to open it" only toast instructions to go type elsewhere. **Why it matters:** the product's one mechanism is the Brief, and its two most consequential buttons bypass it, so the loop breaks exactly where trust is highest. **Fix:** both post a synthesized Brief (file, both copies, differing files, request) through the existing send path, reuse the Sent/Waiting status, fall back to Copy Brief when offline; add each copy's date to `DriftDetail` so the popover shows which is newer. **Command:** /impeccable harden.
3. **[P1] The Mono register changes behaviour, not voice.** The tree is sorted by name while ← → follow server order, so the row below the cursor is not the next page; "drift" is a dead span there; there is no running head. **Why it matters:** the Register is defined as a voice, and this makes it a second product with its own rules. **Fix:** derive pages from the displayed order (or print page numbers in Mono rows and let ← → follow them), wrap the drift span in the popover, restore the running head. **Command:** /impeccable harden.
4. **[P1] Guessed-group actions are cheap to mistake and the names collapse.** "not a group" and `x` dismiss instantly with no Undo; the row's name ellipsizes before its annotations, so three guessed groups become "Installed together, 2…". **Why it matters:** the one destructive-feeling action has no exit, and the rows it sits on are indistinguishable. **Fix:** Sonner `action: Undo` calling `restore`; reveal "name it / not a group" on hover, focus or in a small menu; let the name win the space and wrap or shorten annotations. **Command:** /impeccable clarify, then /impeccable layout.
5. **[P2] The home page repeats itself and the arc drops its thread.** "spellbook" 8×, counts 3×, the frontmatter name above the body's identical H1, an 86-character description line, scrollbars in a 68ch measure, an 11-key legend always on screen. After a reload, note highlights vanish (live `Range` objects detach) and "applied" is asserted on any change. **Fix:** hide a leading H1 that equals the frontmatter name; let code blocks span the column; drop one of the three counts; re-anchor notes by quote text after reload and flash them; say "file changed" unless the quoted text changed. **Command:** /impeccable distill, then /impeccable typeset.

## Minor Observations

- Running heads uppercase the project path to "~/CODE/SPELLBOOK"; paths are case-sensitive.
- `scanned.slice(11, 16)` prints the ISO hour; if the server sends UTC this is the wrong local time.
- Segmented controls have no vertical inset (detector: `cramped-padding` ×3).
- A `transition: height` somewhere in the tree animates layout (detector: `layout-transition`); find it and animate transform or opacity instead.
- Notes aside is sticky with no `overflow: auto`, so Send Brief leaves the screen with many notes.
- Rescan always toasts "Rescanned the roots." because the rejection is swallowed.
- Boot error offers no Retry.
- Highlights depend on the CSS Custom Highlight API; without it the range is silently never shown, contradicting DESIGN.md.
- Copy Brief lives in both the More menu and the Notes footer.
- Settings nav leaders for Connection, Roots, Groups and Keys lead to blank values, and `.lnk.is-current` is never applied.
- "The agent is the only writer" appears three times on the Settings spread.
- Prose keeps server order (alphabetical then plugins) while Mono sorts by name: same book, two orders.
- The review sub-agent switched this browser's persisted Register to mono while testing; flip it back in Settings if you want the default.

## Questions to Consider

- If a Register is only a voice, why does Folio know how to sort, filter and move a cursor while Grimoire cannot? Should the book have one behaviour with two type treatments?
- Page numbers are the book's spine, yet the Brief speaks in paths and lines and the agent never hears "page 17". Should the agent address pages too, or should the footer say "12 of 36 skills" where the conceit is not load-bearing?
- "Name it" and "not a group" create a browser-only memory that disagrees with the disk and every other browser. Is localStorage a third writer, and should a rename be a Brief that records the group in a manifest?
