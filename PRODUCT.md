# Product

## Register

product

## Users

Spellbook is for developers and AI power users who accumulate skills across Claude Code, Cursor, Codex, and similar agents. They use it during active coding sessions and periodic maintenance, often after forgetting what is installed, where it came from, or whether one agent's copy has drifted from another.

## Product Purpose

Spellbook is a native macOS library for discovering, understanding, editing, updating, and removing locally installed agent skills. It turns scattered Markdown files and skill packages into a trustworthy inventory while preserving each agent installation as an independent copy.

Success means a first-time user can open the app, grant only the access that is needed, immediately see their existing skills, understand each skill's source and installation state, and safely act on anything that needs attention.

## Brand Personality

Quiet, lucid, trustworthy.

Spellbook should feel like a well-made native utility: dense enough for experts, calm enough for reading, and precise around filesystem changes. Its personality comes from skill artwork, agent identities, thoughtful typography, and clear behavior rather than decorative interface styling.

## Anti-references

- Generic AI dashboards with blue or purple gradient accents, glowing buttons, oversized cards, or chat-first framing.
- Marketplace-first layouts that make a user's local library feel like a storefront.
- Sparse productivity interfaces that hide useful metadata behind excessive whitespace.
- File managers that expose implementation paths as the primary organizing principle.
- Sync products that silently overwrite local work or imply certainty when provenance is unknown.

## Design Principles

1. Local truth comes first. Show what is actually installed before suggesting anything from the internet.
2. Skills are the reading unit; packages are the source and update unit; installations remain independent.
3. Make state actionable. Surface one clear next action instead of a cluster of passive badges.
4. Never overwrite ambiguity. Preview changes, preserve local edits, and explain when provenance cannot be verified.
5. Earn every pixel. Use compact hierarchy, native conventions, and color only when identity or state benefits from it.

## Accessibility & Inclusion

Target WCAG 2.2 AA where applicable to macOS and support full keyboard navigation, VoiceOver, system text scaling, high contrast, reduced motion, and Increase Contrast. Never encode state by color alone. Compact density is the default, with a comfortable density option and independent reader text sizing.
