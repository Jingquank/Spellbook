Spellbook

Design language & generative thumbnails

Everything the macOS app got right about how Spellbook should look, kept and translated to the web — and the generative thumbnail system, rewritten as working browser code so it keeps producing the same images it always did.

What this repository holds now

The SwiftUI application has been removed. Spellbook's next form is a temporary interface that runs in the browser, opened by the agent from a skill and shaped by whatever codebase it is looking at. That interface does not exist yet. What survives the reset is the part worth keeping: the visual system, and the artwork generator.

Direction

A restrained product language for someone moving quickly between coding agents, then slowing down to read one skill carefully. Two modes, one surface: scan and read.

  • ASIDE — dense lists, compact rows, thin dividers, quiet hierarchy.
  • v0 — direct controls, minimal chrome, an interface that gets out of the way.
  • Codex — calm technical content, disciplined typography, source-aware workflows.

Hierarchy comes from weight, spacing, and a short scale — not from boxes, fills, or color. Color is app-owned and restrained; the only things allowed to be loud are skill thumbnails and official agent logos, which keep their own color entirely.

Color

Four resolved palettes: light, dark, and an Increase Contrast pair. Every role below is a live CSS variable — switch the appearance in the title bar and the swatches follow. The OKLCH values in the original spec remain the design targets; the sRGB seeds are what ships.

Rules that outlive the palette

  • Interaction, focus, link, and update are one warm graphite role. Saturated blue is not an interaction color.
  • Primary buttons use a high-contrast neutral fill with canvas-colored content, never a brand fill.
  • Selection is a neutral tint. It never carries brand hue.
  • Status color appears in exactly three places: the single actionable indicator, destructive confirmations, and diff semantics.
  • Thumbnails and agent marks are identity artwork. They are never tinted, dimmed, or recolored to match the palette.

Typography

Schibsted Grotesk for everything the interface says. Commit Mono for everything the machine says — paths, revisions, hashes, diffs, aligned tables, editor text — with programming ligatures switched off.

Reader prose sits at 15 px with a 1.5–1.6 line height and a 68–74 character measure. Display typography is not used inside the app shell.

Space & shape

Space

Ten steps. Whitespace separates conceptual groups; it is not a decorative resource.

Radius

Five steps, plus capsule at the call site where a control genuinely calls for it.

Stroke

Hairline at 0.5 px and 1 px. Dividers are one physical pixel wherever the display permits. Boundaries are drawn with a separator line, not with a card.

Icons

One semantic vocabulary, vendored from Iconoir at revision 10a66d02. Regular artwork keeps its 24×24 geometry, caps, and joins, with stroke width normalized from 1.5 to 2.0. Solid artwork is reserved for explicit binary states — a completed task, a clear affordance.

Icon color is semantic. Call sites choose a role, never an ad-hoc color.

The vocabulary

46 glyphs. If a concept is not here, it does not get an icon.

Agent marks

Official distribution or brand-kit tiles at 22 px, in original color, with no tint, cropping, effect, or added background. These are identity, not interface.

Provenance, source versions, trademark notes, and SHA-256 digests are recorded in design/icons/AGENT-ASSETS.md, ICONOIR-ASSETS.tsv, and icon-assets.sha256.

Generative skill thumbnails

A skill with no artwork of its own gets a generated one instead of a grey placeholder. The image is deterministic: the same identifiers always produce the same picture, on every machine, in every session. Nothing is random, nothing animates, nothing is written to disk.

How an image is chosen

Three integers seed the drawing, and each comes from a different place on purpose.

SeedDerived fromWhy there
Palette indexPackage id, rolling ×31 hash, mod 7One package reads as one color family
Style indexSkill id, FNV-1a hash, mod 5Siblings in a package stay distinguishable
Category indexInferred from package and skill textRotates color assignment within the palette
 
seed  = paletteIndex × 31 + styleIndex × 7 + categoryIndex
color = palette[(offset + seed) mod palette.length]

Both hashes accumulate in 64-bit unsigned arithmetic and wrap, exactly as the Swift original did — the JavaScript port uses BigInt so it produces byte-identical indices rather than merely similar ones.

The five compositions

Flat fills only, one clipped rounded square, corner radius 22% of the edge. No symbol, no gradient, no animation, no image allocation.

  1. Cropped geometry — an oversized circle and an angled slab, cropped by the frame, with one counterweight dot.
  2. Mosaic tiles — six rectangles on two shifting split lines.
  3. Concentric forms — four nested circles off an off-center anchor.
  4. Radial fan — six wedges from a corner anchor to a fixed boundary.
  5. Woven strips — two vertical and two horizontal rounded bands, with the verticals re-laid over the crossings so the weave reads.

Five more were prototyped and rejected: color bands, category grammar, nested arches, folded ribbon, layered waves.

The 35 combinations

Seven palettes down, five compositions across. This is the whole space, rendered live.

In a sidebar row

Artwork is 18 px in the sidebar and 42 px in the detail header. At 18 px the composition has to survive as a color impression, which is why every composition is flat and edge-cropped.

Resolution ladder

A generated thumbnail is the last rung, not the first. Real artwork always wins, and the source of what is shown is always nameable.

  1. User upload
  2. Package icon declared in the package
  3. Skill icon declared in the skill
  4. GitHub social preview
  5. GitHub organization avatar
  6. README image
  7. GitHub owner avatar
  8. Generated artwork — deterministic, always available, never a spinner

Declared icons are drawn to fit; discovered and generated artwork fills. Category inference scores keyword hits — 5 for the package title, 3 for skill names, 1 for prose — and falls back to General Utility when the winner is weak or contested rather than guessing.

Prohibitions

These held for the macOS app and hold for the web interface. They are the fastest way to tell whether something belongs.

  • No gradient text, decorative gradients, glass cards, glowing actions, or blue-filled controls by default.
  • No card grid for the library.
  • No nested cards in details or settings.
  • No decorative particles, fantasy ornament, or medieval styling, despite the name.
  • No multiple status badges competing inside one row.
  • No ad-hoc color at a call site. Roles only.
  • One surface owner per control. A quiet icon button gets one hover surface, not a nested pair.

Carried over, not yet re-derived

Parts of the original system described a native macOS window rather than a visual language. They are recorded here as intent, to be re-decided once the web interface has a shape — not quietly translated into web rules they were never written for.

  • App shell — a two-pane split view, a system-owned toolbar, and a fixed 40 px plain title bar. The two-pane idea survives; the window chrome does not apply.
  • SF Symbols allowlist — the narrow exception for macOS-owned menus, empty states, and window chrome. On the web there is no such owner, so the Iconoir vocabulary stands alone.
  • Scroll-edge veils — an 18 px material blur plus a sidebar-color fade, shown only while content continues past the edge. The behavior is right; the material needs a web equivalent.
  • Appearance settings — appearance, density, interface text size, reader width, and code wrapping. All five still make sense; where they live in a transient interface is an open question.
  • Actionable status indicator — at most one per row, highest priority wins: conflict or action required, then locally modified, then update available. This survives intact.

Using these files

Tokens

<link rel="stylesheet" href="design/tokens.css">

.skill-row {
  height: var(--sb-sidebar-row-compact);
  padding: 0 var(--sb-sidebar-inset-x);
  border-radius: var(--sb-radius-medium);
  font: var(--sb-weight-regular) var(--sb-type-row-label) var(--sb-font-ui);
  color: var(--sb-text-primary);
  transition: background-color var(--sb-duration-hover) var(--sb-ease-out);
}
.skill-row:hover { background: var(--sb-hover); }

Set data-theme on the root element to force light, dark, hc-light, or hc-dark. Leave it off to follow the system.

Thumbnails

<script src="design/thumbnails.js"></script>

const spec = SpellbookThumbnails.thumbnailFor({
  packageId: "anthropics/skills",
  skillId:   "anthropics/skills/pdf",
  packageName: "Anthropic Skills",
  skillNames: ["pdf", "docx", "xlsx"],
  prose: "Fill and extract PDF forms…"   // category is inferred if omitted
});

SpellbookThumbnails.render(canvasElement, spec, 42);   // sizes for the display
SpellbookThumbnails.toDataURL(spec, 18);               // or a PNG data URL
